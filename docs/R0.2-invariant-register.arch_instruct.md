# R0.2 — Invariant Register

**Class:** arch_instruct · **Pass:** R0 · **Status:** issued
**Depends on:** R0.1
**Touches:** `docs/INVARIANTS.md` (new)

---

## 1. Decision

Every invariant in `PSYKI_CORE.md` §2 is assigned an **enforcement status** and a
**named test file**. An invariant with no executing test is labelled
**ASPIRATION** in the register and in CORE itself, and may not be cited as a
security property anywhere in the repo until it has one.

---

## 2. Why

The v0 README claimed *"determinism test is a CI gate."* There is no `.github/`
directory in this repository. There is no CI. The test file exists
(`test/test_determinism.py`) and, as far as anyone knows, nothing has ever run it
on a commit.

That is the pattern to kill. Twelve invariants are currently asserted in prose
and enforced by nothing. The security argument for this entire architecture —
that a compromised Emissary can only express what the enum vocabulary allows,
that KI cannot be prompt-injected because it never reads text, that the server
cannot rewrite its own charter — rests on invariants none of which are checked
at merge time.

The register does not fix this. It makes it impossible to forget.

---

## 3. Status vocabulary

| Status | Meaning |
|---|---|
| **GATED** | test exists, runs in CI, blocks merge |
| **TESTED** | test exists and passes, not wired to CI |
| **PARTIAL** | some cases covered, known gaps documented |
| **UNVERIFIED** | implementation claims to satisfy it; nothing checks |
| **ASPIRATION** | no implementation exists yet |

Only **GATED** counts as enforcement. Everything else is a promise.

## 5. Additional invariants CORE does not state but the design requires

These are gaps in CORE, surfaced here rather than silently assumed.

| # | Proposed invariant | Why CORE needs it |
|---|---|---|
| **I13** | The Emissary's encode is verifiable. A single encode is not trusted. | CORE §4.1 says a silently lossy Emissary is *"the worst failure this design admits, because nothing downstream can detect it"* — and then provides no detector. An undetectable critical failure is not a design, it is an acknowledged hole. Candidate mechanisms: independent double-encode with agreement required, or enum→NL→re-encode round-trip stability. Owner: R2.1. |
| **I14** | There exists a human abort path that halts the loop within one cycle, independent of Wall, PSY, and KI. | CORE §6 states the loop `Emissary→Wall→PSY→KI→AgentAgent→execution→Emissary` *"has no human in it"* and that the replan counter is the only halt guarantee. A counter guarantees termination eventually; it does not guarantee termination *now*. An autonomous system with credentials and no stop button is the single highest-severity item in this register. Owner: R2.4. |
| **I15** | Retinue toolset signatures include tool version. | CORE §10.3 raises this as open. A tool changing beneath a cached, hash-pinned agent is a silent correctness failure, not a loud one. Owner: R3. |

**I14 is recommended for immediate promotion into CORE §2** rather than waiting
for R2. It costs nothing to specify and its absence is unacceptable the moment
anything in this system holds a credential.

## 6. Flaw enumeration

- **The register can be gamed.** A trivial test that technically executes flips an invariant to TESTED without establishing anything. Mitigation: every test named here must include at least one *negative* case that fails when the invariant is deliberately violated. A test that cannot fail is not a test. This should itself become a CI check in R1.3 (mutation testing), which is more work than it sounds.
- **Static import checks are evadable.** The AST bans proposed for I3 and I11 are defeated by `importlib`, `getattr`, or `eval`. They raise the cost of an accident to near-certain detection, and the cost of deliberate subversion to almost nothing. They are anti-drift measures, not security controls, and must not be described as security controls.
- **Six ASPIRATIONs are structural, not lazy.** I8–I12 cannot be tested because the types they constrain do not exist. This register will look bad until R2 lands and there is nothing to do about that. Reporting the ratio honestly each pass is the point.
- **The register duplicates CORE §2.** Two documents listing invariants is exactly the failure R0.1 deletes the PDF over. Mitigation: CORE §2 keeps the *statements*; `docs/INVARIANTS.md` holds *status only*, referencing CORE by number and never restating an invariant's text. If it ever restates one, delete the restatement.
